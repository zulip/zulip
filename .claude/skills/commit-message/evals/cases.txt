# The commits used as eval cases. See README.md.
#
# How they were chosen:
#
# - The target style is how Tim Abbott and Lauryn Menard write, with
#   no AI help. Claude Code launched in February 2025, and the first
#   commit here with a Claude co-author line is from February 2026.
#   So the cases come from commits that landed in 2023 and 2024:
#   1,558 non-merge commits, 654 by Tim and 904 by Lauryn.
# - All cases were picked at random within fixed groups, so that the
#   set covers the kinds of commit a skill must handle.
# - 80 cases are grouped by author and body length. They come from
#   commits that change 3 to 700 lines and have no upkeep word in
#   the summary. Each author has 8 with no body, 12 with 1-3 lines,
#   14 with 4-9 lines, and 6 with 10 or more. About 30% of their
#   commits have no body, so a good skill must also know when to
#   write none.
# - 10 cases have a word in the summary that often marks routine
#   upkeep, such as "typo", "version", "upgrade", or "changelog".
# - 5 cases change fewer than 3 lines, and 5 change more than 700.
#
# The cases were not picked by hand or by type of change. The mix of
# bug fixes, refactors, docs, and migrations is what random sampling
# gave.
#
# The no-body and small cases are the hardest. With only the diff to
# go on, the current skill still writes a short body for most of
# them. See "Known limits" in README.md.
#
# Format: <hash> # <commit summary>
#
# Summaries are copied exactly, typos included, so
# tools/run-codespell skips this file.
