* [`POST /register`](/api/register-queue): Added a `long_term_idle`
  boolean to the response, for whether the current user's account is
  long-term idle, along with a `long_term_idle_days` integer for how
  long they have been away. Added the `long_term_idle_reactivation`
  client capability, which asks the server to ready such an account in
  the background and return those two fields with no other data about
  the organization or the user, rather than making the request wait for
  the account to be ready.
* [`GET /events`](/api/get-events): Added a `long_term_idle` event,
  sent when the user stops being long-term idle, so that a client
  waiting for their account can register again.
