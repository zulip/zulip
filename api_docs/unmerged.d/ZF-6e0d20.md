* [`POST /register`](/api/register-queue): Added a `long_term_idle`
  boolean to the response, for whether the server is still
  reactivating a returning long-term-idle user's account in the
  background. Added the `long_term_idle_reactivation` client
  capability, which asks the server to do that reactivation in the
  background and return `long_term_idle: true` with no other data
  about the organization or the user, rather than making the request
  wait for the account to be ready.
* [`GET /events`](/api/get-events): Added a `long_term_idle` event,
  sent when the user stops being long-term idle, so that a client
  waiting for their account can register again.
