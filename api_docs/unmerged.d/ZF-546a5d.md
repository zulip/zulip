* [Rate limit error handling](/api/rest-error-handling#rate-limit-exceeded): The
  `retry-after` value in rate limit error responses, and the
  [`Retry-After` HTTP header](/api/http-headers#rate-limiting-response-headers),
  are now always an integer number of seconds, rounded up. Previously,
  both were an unrounded number of seconds, which could describe a wait
  shorter than the client's round trip to the server.
