* [`GET /users/me/watched_phrases`](/api/get-watched-phrases),
  [`POST /users/me/watched_phrases`](/api/add-watched-phrases),
  [`DELETE /users/me/watched_phrases`](/api/remove-watched-phrases): Added
  new endpoints for configuring the current user's [alert
  words](/help/dm-mention-alert-notifications#alert-words), which
  represent each one as an object rather than a string, so that
  per-phrase configuration can be expressed. The previous
  `/users/me/alert_words` endpoints remain supported, but cannot
  express that configuration.

* [`POST /register`](/api/register-queue): Added a `watched_phrases`
  field, present if `watched_phrases` is in `fetch_event_types`, which
  contains an object for each of the current user's alert words. The
  `alert_words` field is now deprecated in favor of it.

* [`GET /events`](/api/get-events): Added a `watched_phrases` event
  type, sent whenever the current user's alert words or the
  configuration of any of them change. The now deprecated `alert_words`
  event type is still sent alongside it, but only when the set of alert
  words itself changes, since it cannot express that configuration.

* [`POST /users/me/watched_phrases`](/api/add-watched-phrases),
  [`POST /register`](/api/register-queue), [`GET /events`](/api/get-events):
  Added an `automatically_follow_topics` field to watched phrase objects,
  which controls whether the user automatically [follows
  topics](/help/follow-a-topic) that receive a message containing that
  phrase.
