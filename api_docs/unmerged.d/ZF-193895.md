* `POST /bots`: Incoming-webhook bots now take the integration in the
  `integration_id` key of `config_data`, instead of the `service_name`
  parameter. Sending `service_name` for an incoming-webhook bot now
  returns an error.
* `POST /bots`: Sending `payload_url` for a bot that is not an
  outgoing-webhook bot now returns an error. Previously,
  `payload_url` was silently ignored for generic and incoming-webhook
  bots, and silently stored (but unused) on the `Service` row for
  embedded bots.
* `POST /bots`: The `config_data` parameter is now only accepted for
  incoming-webhook and embedded bots; sending it for other bot types
  returns an error. Previously, it was silently ignored.
* `POST /bots`: Sending `service_name` for a generic bot now returns
  an error. Previously, `service_name` was silently ignored for
  generic bots.
* `POST /bots`: The `interface_type` parameter is now only accepted
  for outgoing-webhook bots; sending it for other bot types returns
  an error. Previously, it was silently ignored for generic and
  incoming-webhook bots, and silently stored on the `Service` row
  for embedded bots.
