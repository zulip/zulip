* [`GET /calls/jitsi/create`](/api/create-jitsi-video-call): Added a new
  endpoint to generate a Jitsi Meet video call URL with JWT
  authentication.

* [`POST /register`](/api/register-queue): Added `jitsi_jwt_enabled`
  boolean field to the response, indicating whether JWT-authenticated
  Jitsi Meet calls are usable for the current realm.

* [`POST /register`](/api/register-queue): Added
  `server_jitsi_jwt_configured` boolean field to the response,
  indicating whether the Zulip server has JWT credentials set for its
  configured Jitsi Meet server.

* [`GET /events`](/api/get-events): The server now sends a
  [`realm` op: `update_dict`](/api/get-events#realm-update_dict) event
  instead of a [`realm` op: `update`](/api/get-events#realm-update)
  event when a realm's `jitsi_server_url` property is changed. The
  event's `data` carries both `jitsi_server_url` and the recomputed
  `jitsi_jwt_enabled`, so clients can update both fields together.
