* [`GET /calls/jitsi/create`](/api/create-jitsi-video-call): Added a new
  endpoint to generate a Jitsi Meet video call URL with JSON Web Token
  (JWT) authentication.

* [`POST /register`](/api/register-queue): Added
  `server_jitsi_jwt_configured` boolean field to the response,
  indicating whether the Zulip server has JSON Web Token credentials set
  for its configured Jitsi Meet server. This field will always be false
  when the `server_jitsi_server_url` in the response is `null`. Combined
  with `realm_jitsi_server_url`, clients should use this to decide
  whether to invoke the new JWT-signed call flow.

* [`POST /register`](/api/register-queue): The client contract for
  `realm_jitsi_server_url` and `server_jitsi_server_url` was extended.
  Now, when `server_jitsi_jwt_configured` is `true` and
  `realm_jitsi_server_url` is `null`, clients must call
  [`GET /calls/jitsi/create`](/api/create-jitsi-video-call) to obtain a
  call URL. Previously, clients could generate a Jitsi Meet call URL by
  constructing one from these two fields directly; see feature level 212.
